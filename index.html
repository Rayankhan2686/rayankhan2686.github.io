Strapdown IMU AHRS

A strapdown attitude and heading reference system built from scratch in Python and C++. Two fusion filters, a complementary filter and a quaternion-based Madgwick filter, run unchanged on synthetic data, recorded logs, and a live ESP32 and IMU. The complementary filter holds attitude to 0.25° RMS, a 1200× improvement over raw gyro integration.

Problem
Estimate accurate 3D attitude and heading from noisy, drifting IMU sensors. Raw gyro integration alone drifts hundreds of degrees over time.
Approach
An ESP32 Feather V2 with an ICM-20948 9-DoF IMU streams raw sensor data to a Python host running complementary and Madgwick fusion filters implemented from first principles; architected as "dumb firmware, smart host" with a transport-agnostic parser so the same filter code runs unchanged on a synthetic ground-truth generator, a recorded CSV, or a live UDP stream.
Tradeoffs
The nav frame is +Z-up (ENU-style), not the aerospace-standard NED, so a flat, stationary board reads accel ≈ [0, 0, +1] g directly, one less sign flip to get wrong when cross-checking real hardware. Both filters still use the standard ZYX yaw-pitch-roll (3-2-1) sequence. The bigger tradeoff is representation: the Tier-1 complementary filter fuses accelerometer and gyro directly in Euler angles, which is simple but degenerate near ±90° pitch, where roll and yaw lose their distinction. Driving true pitch to 90° in the ground-truth simulator confirms it: the Euler-based filter's error grows to 1.54° near the pole, while the quaternion-based Madgwick filter, whose internal state never passes through that coordinate singularity, stays at 0.65° max error over the same maneuver. That measured comparison, not intuition, is why the Tier-2 filter is quaternion-based rather than a refined Euler filter.
Results
Over a 600 s static run with a 0.5°/s gyro bias, the complementary filter holds attitude to ~0.25° RMS versus ~300° of raw gyro-only drift, roughly a 1200× improvement. On a known-angle roll sweep (0°→45°→0°) it tracks true roll to ~0.12° RMS after a 1 s startup transient. Validated by a 32/32 passing test suite covering parsing, the simulator, both filters, the UDP transport, and the visualization geometry.

Camber Effects on Airfoil Aerodynamics

An OpenFOAM and Python pipeline studying how camber affects lift, drag, and stall on NACA 0012, 2412, and 4412 airfoils at Re = 2×10⁵. Built from mesh generation through post-processing and validated against XFOIL across 87+ RANS simulations. A meshing defect that silently corrupted early results was traced and fixed, correcting the lift coefficient by roughly 5×.

Problem
Quantify how camber (NACA 0012/2412/4412) affects lift, drag, and stall behavior at Re = 2×10⁵, building the full OpenFOAM/Python pipeline (meshing through post-processing) from scratch instead of treating the solver as a black box.
Approach
Automated an OpenFOAM/Python pipeline (STL generation → blockMesh → simpleFoam with k-ω SST → force-coefficient extraction) and ran 87+ steady RANS cases across a −4° to 20° angle-of-attack sweep at 0.5° resolution near stall, checking every result against XFOIL and a dedicated mesh-independence study rather than trusting a single mesh.
Tradeoffs
An early mesh used snappyHexMesh, which refines cells in all three directions near the airfoil surface, silently splitting the single spanwise cell into two even though the case was meant to be strictly 2D. The defect didn't crash the solver or show up in residuals; it surfaced only as OpenFOAM's checkMesh flagging the mesh "not 1D or 2D." Before trusting that diagnosis, I ruled out the more common suspects one at a time: force-direction vectors, reference area, a mis-read results column, degenerate STL geometry, all confirmed correct against the case's own log files. That process of elimination pointed at the mesh itself. I rejected two cheaper patches (thickening the span to dilute the z-split; excluding a snappyHexMesh refinement region near the surface) as unreliable, and instead rebuilt meshing around blockMesh's project feature (following the compressible/rhoSimpleFoam/aerofoilNACA0012 tutorial pattern) to snap block vertices directly onto the airfoil surface with a guaranteed single-cell span.
Results
The corrected mesh raised Cl at α = 6° from 0.109 to 0.583 (below), consistent with thin-airfoil theory, and the full sweep validated to within roughly 4% of XFOIL for attached flow (α = −4° to 7°). A follow-up mesh-independence study found α ≥ 8° does not converge under refinement: Cl and Cd reverse trend direction rather than shrink across four mesh tiers, so that range is flagged as unreliable and excluded rather than reported as clean data.
Next
Preparing these results for an AIAA SciTech publication.
  • Before (snappyHexMesh, non-2D mesh, checkMesh flagged): Cl = 0.109 at α = 6°.
  • After (blockMesh C-grid, verified 2D): Cl = 0.583 at α = 6°, roughly a 5× correction.

pyFEA (in progress)

Problem
Understand finite element analysis from first principles instead of treating commercial solvers as black boxes.
Approach
3D FEA solver in pure Python. Tet4/Tet10 elements, sparse global stiffness assembly, von Mises stress recovery, gmsh meshing, Streamlit 3D viewer.
Tradeoffs
Tet10 is the default element even though Tet4 assembles faster: a linear Tet4 can only represent constant strain per element, so it needs a much finer mesh to resolve a bending gradient, while the quadratic Tet10 captures that gradient at a coarser element count. Validating a cantilever against Euler-Bernoulli theory shows the tradeoff directly: tip deflection matches to within 0.1% on a coarse mesh, but peak root stress still under-predicts by ~11%, because nodal averaging and the Saint-Venant boundary layer at the fully-clamped root both blur the true peak; closing that gap needs local refinement at the cost of a slower solve. Singularity is also checked cheaply rather than exactly: before solving, the assembled stiffness matrix is scanned for any free degree of freedom left with an all-zero row after boundary conditions are applied, a fast, necessary-but-not-sufficient guard against unconstrained rigid-body modes. It catches the common case (a node left completely unconstrained) but not a rigid-body mode coupled across several DOFs, which would need a full rank or eigenvalue check to detect.
Results
Cantilever (Tet10, 2,395 elements): tip deflection within 0.1% of the Euler-Bernoulli prediction; root von Mises stress under-predicts by 11.3%, consistent with the boundary-layer effect above. Plate-with-a-hole: FE stress-concentration factor Kt = 2.72 vs. the Pilkey finite-width reference of 2.51 (8.6% error).
Next
Additional element types and validation cases.
